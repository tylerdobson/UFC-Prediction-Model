# Data source decision record

Checked 2026-09-26. This records the source assumptions for the **pre-fight** release; verify current terms and account limits before production use. The repository has adapters, offline fixtures, and a separate Wikipedia research-history import. It has no configured live API keys or checked operating history. Provider descriptions below are claims from their own documentation, not independent coverage tests or a grant of downstream rights.

The operator confirmed that free API accounts are acceptable. No paid historical-odds plan or live key has been selected or configured.

## Source acceptance gate

Before using a feed for model decisions, save a raw dated payload and ingestion receipt, link provider fighter IDs explicitly, and sample-check imported cards against the source. Measure card completeness, substitutions, cancellations, results, quote match rate, two-sided same-book coverage, and source/update/capture age. Keep rejected or ambiguous items visible in the audit and out of decisions.

## Remaining operator choices

1. Choose and obtain continued, betting-compatible rights to a primary fight-history source or provide a reviewed rights-cleared CSV history. Send the [prepared UFCalendar rights inquiry](PROVIDER_RIGHTS_REQUEST.md), seek a Sportradar betting-use agreement, or request a scoped SportsDataIO MMA license; none of the trials establishes operating rights. Use the Wikipedia result bootstrap separately for historical model research, with attribution and independent accuracy checks.
2. Configure a free Odds API key for prospective quote collection, or choose another feed with documented rights and timestamp semantics.
3. Decide whether named-book historical odds access is worth paying for after prospective coverage is measured. UFCalendar's consensus history can inform a separate research baseline only when its timestamp is known before the decision cutoff; a closing line or unidentified consensus cannot establish a realizable betting return. The app can still be useful as a forecasting and research product without historical betting ROI.

Store keys only in the local/server environment. Do not commit keys, raw licensed payloads, or a live database to the private repository.
